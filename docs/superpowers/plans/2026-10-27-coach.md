# Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Coach page and a weekly email that turn a student's whole test history into a short, evidence-backed path to a higher band.

**Architecture:** A deterministic facts layer (`apps/server/src/coach/`) reads attempts, analyses, mistakes and L/R attempts and computes every number, pattern and candidate with its evidence IDs. One cheap model call words the report from those facts; a validator drops anything uncited and falls back to templates. Reports are daily snapshots, generated by an hourly sweep or on page open, only after a new test; the weekly email reuses the latest snapshot.

**Tech Stack:** Hono + @hono/zod-openapi, drizzle (Postgres), vitest, React Email, Vite/React + TanStack Router/Query, OpenRouter via `chatJson`.

**Spec:** `docs/superpowers/specs/2026-10-27-coach-design.md` (mockup: https://claude.ai/artifact/JDSDZMSZfLtTstMmcU1cSm)

## Global Constraints

- Models: `openai/gpt-6-luna`, fallback `deepseek/deepseek-v4.1-flash`. No Qwen. Cost stage `coach`.
- At most one generated report per user per local day, and only when a test finished after the latest report. No model call otherwise.
- The weekly email makes no model call.
- Every number shown comes from the facts layer; the model may not introduce numbers. No evidence, no item.
- Never compare a student with other users.
- Copy talks about the work, never the person; no guilt-tripping. Plain, friendly NextBand voice; brand "NextBand" (no "IELTS" in the brand).
- UI: WCAG AA, light and dark, existing UI kit (`apps/web/src/components/ui`).
- After API schema changes: `pnpm gen:api` and commit `apps/web/src/openapi.json` and `apps/web/src/lib/schema.d.ts`.
- Before the first real (paid) model call: look up current prices on the OpenRouter model pages and tell the owner the cost per report and per 1,000 active users per day.
- Server tests: `cd apps/server && npx vitest run <file>`. Web tests: `cd apps/web && npx vitest run <file>`.
- Commit after each task; push only when the owner asks. No attribution lines in commit messages.

## Review Focus

1. A student with tests in only one skill, or only Listening/Reading: the page still renders that skill, and the summary says what it can (needs at least 2 skills for the overall line). Test in Task 3.
2. Old analyses missing newer fields (`metrics.lexical`, `structure`, `relevance[].development`, `pronunciation`) and partial L/R attempts (`band` null): facts build without throwing; partial attempts count for patterns, not bands. Test in Task 4.
3. Local-day boundaries: a student in `America/Los_Angeles` testing at 23:30 and again at 00:30 local gets two reports on two days; an unknown or invalid timezone falls back to UTC. Test in Task 6.
4. Two refreshes at once (page open during the sweep, or two server processes): exactly one report row and one model call. Test in Task 6.
5. The model returns an item whose text has a number not in the cited facts, or cites an unknown candidate ID: that item falls back to its template line; the report still saves. Test in Task 5.

- Produces (in `rules.ts`), each pure:
  - `skillFacts(skill: Skill, scored: { at: Date; band: number }[], target: number | null): SkillFacts` — band = mean of last 5 rounded with `roundBand`; range ±0.5; `calibrating` below 3 tests with `needMore = 3 - tests`; with ≥6 tests compare mean(last 3) vs mean(previous 3): ≥ +0.5 `improving`, ≤ −0.5 `slipping`, else `steady`; 3–5 tests `steady`.
  - `overallFacts(skills: SkillFacts[]): CoachFacts['overall']` — null unless ≥2 skills have a band.
  - `isPattern(occurrences: { attemptId: string }[]): boolean` — ≥2 distinct tests or ≥3 occurrences.
  - `windowed<T extends { at: Date }>(items: T[], now: Date): T[]` — last 60 days, capped to the newest 15 tests per skill.
  - `priority(gap: number | null, share: number, kind: string): number` — `(gap === null ? 0.5 : Math.max(gap, 0.25)) * share * FIXABILITY[kind]`; `FIXABILITY` table in this file (high 1.0: `plural`, `spelling`, `word-limit`, `tfng-false-for-ng`, `ideas-undeveloped`, `under-length`; medium 0.7: grammar categories, collocation, word-choice, question-type accuracy, passage timing; low 0.4: pronunciation sounds, fluency measures; default 0.5).
  - `pickCandidates(all: Candidate[]): Candidate[]` — sorted by score descending, top 6 (the 2-per-skill limit applies to the final 3 focus items, in Task 5's validator).
  - `findWin(older: Candidate[], recentTests: Record<Skill, string[]>, skills: SkillFacts[]): Candidate | null` — a pattern in ≥3 older tests and none of the last 3 tests of that skill, else an `improving` skill; at most one.
  - `spellRule(typed: string, correct: string): SpellGroup['rule']`.
